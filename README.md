# 供应商主体审校台

用于归集两套采购系统中的供应商记录：审核企业名称相同的记录对，给出“同一企业 / 不同企业”判定，最终形成入仓时使用的统一主体分组。

- 后端：FastAPI + SQLite（WAL、`BEGIN IMMEDIATE` 事务、`busy_timeout`）
- 前端：单页审校网页，无外部依赖
- 运行形态：Docker Compose 启动 **两个独立 Web 进程**（`app1`、`app2`），nginx 作为浏览器入口轮询转发，两个进程共享同一个 SQLite 数据卷
- 浏览器入口：**http://localhost:8080**

## 快速启动

前置条件：Docker 与 Docker Compose v2。

```bash
docker compose up --build
```

等待两个应用健康检查通过后打开：

**http://localhost:8080**

首次启动会从 `data/suppliers.csv` 导入最多 100 条 `来源 / 源编号 / 企业名称` 记录；本仓库附带 62 条示例记录（两套采购系统各 31 条）。之后原始记录只读，重启不会重新导入，也不会覆盖已有判定和分组。

停止：

```bash
docker compose down
```

如需清空审核数据、从 CSV 重新演示（**会删除数据卷中的全部判定与分组**）：

```bash
docker compose down -v
docker compose up --build
```

## 演示路径

### 1. 合并同名企业

1. 页面默认展示 62 条原始记录、62 个单条分组。
2. 在“同名企业候选对”中找到“华信精密制造有限公司”（A-001 / B-001），点击“同一企业”。
3. 页面先弹出预览：受影响记录的变更前/变更后分组、判定依据、变更摘要。
4. 点击“确认保存判定与分组”。返回后分组变为 61 个，“已归并分组”增加 1。
5. 用“判定工作台”再选另一条已归并记录与第三条记录判定“同一企业”，可看到同一关系传递成组（三条记录进入同一分组）。

### 2. 不同企业约束与冲突拦截

1. 对同一分组内的两条记录选择“不同企业”，预览会显示拦截原因和“同一企业”传递路径，不提供确认按钮。
2. 对两个不同分组选择“不同企业”可正常保存；此后任何会把这二者合并的“同一企业”判定都会在预览时被拒绝。

### 3. 撤回只移除一条判定

在“判定依据”或分组卡片中点击某条判定的“撤回”：

1. 先预览“撤回后分组”，例如一个分组拆成两个分组。
2. 确认后只删除该一条判定，其余同一企业关系继续生效，分组自动重算。

### 4. 两个 Web 进程

页面右上角的“服务进程”显示本次响应来自 `app1` 还是 `app2`。点击“刷新”多次，nginx 会在这两个进程之间轮询；无论请求落到哪个进程，看到的分组与判定都一致，因为预览和确认都通过共享 SQLite 完成。

```bash
docker compose logs -f app1 app2
```

也可以在日志中看到两个进程分别处理请求的访问记录。

也可以直接观察响应头：

```bash
for i in 1 2 3 4; do
  curl -s -D - -o /dev/null http://localhost:8080/health | grep -i x-app-instance
done
```

### 5. 确认时的重新校验（两个标签页演示）

打开两个浏览器标签页，均指向 http://localhost:8080。

**相关改动 → 拒绝并要求重新预览：**

1. 标签页 1：对 A-001 与 B-001 点“同一企业”，停留在预览弹窗，不确认。
2. 标签页 2：对 B-001 与另一条记录（例如 A-002）判定“同一企业”并确认。
3. 回到标签页 1 点击确认：系统会重新读取所涉原组成员（A-001、B-001 及其原分组）和这些成员关联的判定，发现 B-001 的关联判定已变化，返回“预览已失效”，判定与分组均未改变。
4. 点击弹窗中的“重新预览”，确认新的前后分组后再保存。

**无关分组改动 → 不影响确认：**

1. 标签页 1：对 A-001 / B-001 预览“同一企业”，不确认。
2. 标签页 2：对完全无关的“恒达电子科技有限公司”两条记录判定“同一企业”并确认。
3. 标签页 1 直接确认仍会成功；预览只锁定所涉分组及关联判定，无关分组的变化不会阻塞。

## 数据与配置

### CSV

默认文件：`data/suppliers.csv`

支持中英文表头别名：

| 含义 | 可识别表头 |
| --- | --- |
| 来源 | `来源`, `source`, `系统`, `采购系统` |
| 源编号 | `源编号`, `source_code`, `code`, `编号` |
| 企业名称 | `企业名称`, `name`, `企业名`, `供应商名称` |

首次导入按行顺序取前 `SEED_LIMIT` 条（默认 100）。要使用自己的 CSV，可在首次启动前替换该文件，或通过环境变量指定挂载路径：

```yaml
environment:
  SEED_CSV: /app/data/my_suppliers.csv
  SEED_LIMIT: "100"
```

也可在 `docker-compose.yml` 中新增只读挂载：

```yaml
volumes:
  - ./my_suppliers.csv:/app/data/my_suppliers.csv:ro
```

### 环境变量

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `DB_PATH` | `./data/review.db` | SQLite 数据库路径；Compose 中为 `/data/review.db` |
| `SEED_CSV` | `./data/suppliers.csv` | 首次导入的 CSV |
| `SEED_LIMIT` | `100` | 首次导入的最大记录数 |
| `APP_INSTANCE` | 主机名 | 页面展示的 Web 进程标识 |

## 行为与一致性规则

1. **原始记录不可变**：API 不提供修改/删除记录的入口；数据库还有 `BEFORE UPDATE/DELETE` 触发器直接拒绝修改。CSV 只在 `records` 表为空时导入。
2. **判定唯一**：规范化记录对 `(min_id, max_id)` 上最多一条判定。重复添加相同判定会被拦截；对已有相反判定的记录对重新判定也会被拦截。
3. **同一企业传递成组**：分组是“同一企业”边的连通分量。
4. **不同企业是硬约束**：任一“不同企业”判定连接的两个分组不得合并；端点已经在同组时添加“不同企业”判定会被拒绝。
5. **预览**：服务端计算并保存一份快照，包含：
   - 所涉原组成员 `involved_ids`；
   - 这些成员的当前分组及完整组员；
   - 任一端点属于所涉成员的全部生效判定。
   页面展示受影响记录的变更前/变更后分组、组员和判定依据。
6. **确认**：在 `BEGIN IMMEDIATE` 写事务中重新读取当前数据，重建同样的快照并与预览快照逐字段比较：
   - 不一致（相关成员或关联判定发生变化）→ 409，预览标记为 `stale`，**不写入任何判定/分组**，要求重新预览；
   - 一致 → 在同一事务内写入/删除判定、重算并覆盖保存 `groups` 与 `group_members`，再将该预览标记为 `confirmed`。
   与所涉分组无关的判定/分组变化不在快照内，因此不会影响确认。
7. **失败保留原状态**：判定与分组在同一事务提交；任何异常回滚，原判定和原分组保持不变。
8. **重启保留**：判定、预览与分组均在 SQLite 中；启动时若记录已存在则不重新导入，并依据判定重算、规范化分组表。
9. **并发**：两个进程各自按请求打开 SQLite 连接；WAL 允许多读单写，`BEGIN IMMEDIATE` + `busy_timeout` 串行化写事务。同一个预览被并发确认时只有一次成功，另一次得到“预览不可再次确认”。

## API 摘要

同一组 API 会被 nginx 分发到两个进程，任意进程都能处理任意预览/确认。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/state` | 当前记录、分组、判定依据、同名候选对、统计 |
| `POST` | `/api/previews` | 创建预览：`{"operation":"add","record_a":1,"record_b":2,"relation":"same"}` 或 `{"operation":"withdraw","decision_id":3}` |
| `POST` | `/api/previews/{id}/confirm` | 确认；body `{"snapshot_digest":"..."}` 可选，用于校验页面持有的是同一预览 |
| `POST` | `/api/previews/{id}/cancel` | 取消尚未确认的预览 |
| `GET` | `/health` | 健康检查，返回进程实例 |
| `GET` | `/api/meta` | 初始化信息与预览状态统计 |

冲突预览返回 HTTP 200，但 `preview.confirmable=false` 且附带 `conflict.code/message/evidence`；过期确认返回 HTTP 409。

## 本地开发与测试

```bash
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements-dev.txt
uvicorn app.main:app --port 8000
```

浏览器打开 http://localhost:8000（单进程本地模式）。

运行测试：

```bash
pytest -q
```

测试覆盖：首次导入上限与记录不可变、同关系传递、不同关系冲突、撤回单条判定、跨进程预览/确认、相关改动导致预览过期、无关改动不阻塞确认、同一预览只能确认一次、持久化分组表与重启恢复等。

```text
  db.py              SQLite 连接、建表、一次性 CSV 导入、记录只读触发器

  service.py         预览快照、确认重校验、原子保存、页面状态
  static/index.html  审校网页

tests/test_review.py 自动化测试
nginx/nginx.conf     nginx 轮询入口
Dockerfile
docker-compose.yml   两个 Web 进程 + 网关 + 共享数据卷
```
